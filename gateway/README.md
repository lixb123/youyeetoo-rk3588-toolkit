# 风火轮 RK3588 双网口演示

`youyeetoo_eth_gateway` 在板端以 root 运行，使用 AF_PACKET 监听两个物理口，并对 IPv4/UDP 报文按文档中的地址分类。内核仍负责标准 ARP、IPv4 转发和透传；程序只对协议端口 `47000` 的应用数据解码并打印，不改变原始报文。它始终是一个程序，同时监视载荷口和 X 测控口，不提供图形界面。

## 板端编译与运行

```sh
make
sudo ./configure_gateway.sh eth0 eth1
sudo ./youyeetoo_eth_gateway --payload-iface eth0 --x-iface eth1
```

程序的所有正常输出和错误输出都会继续发送到当前串口终端，同时追加写入可执行文件同级的
`youyeetoo_eth_gateway.log`。这样从任意目录启动或复制程序时，日志都跟随程序，不依赖当前工作目录或系统日志目录。

默认地址：载荷口 `10.240.1.34/24`，X 测控口 `10.240.1.1/30`。如果板上网口编号相反，只交换最后两个参数。输出中的 `priority=0/1/2/3` 分别表示上注、业务/S1、管理与日志、其他；协议字段按《以太网通信协议 星移》大端格式解析，校验和不包含 `0xEB90/0x1ACF` 标识符。

配置脚本会清理所选网口旧 IPv4 地址；UART 控制口不受影响。若网卡驱动拒绝 `tc prio`，脚本会继续完成地址和转发配置，并在输出中告警，程序仍会打印每帧的文档优先级。

## 通道映射

| IP | 处理 |
|---|---|
| `10.240.1.35` <-> `10.240.1.51` | 基站管理/日志，透传，优先级 2 |
| `10.240.1.36` | 卫星平台交互/软件上注，解析协议，优先级 0 |
| `10.240.1.37` <-> `10.240.1.40` | S1-C/S1-U，透传，优先级 1 |
| `10.240.1.38` <-> `10.240.1.50` | N6 业务，透传，优先级 1 |
| `10.240.1.39` <-> `10.240.1.52` | 核心网管理/日志，透传，优先级 2 |
| `10.2.1.0/16` | 不过滤，路由到 `10.240.1.38`，优先级 1 |

`tc prio` 配置与程序输出的优先级保持一致。PAUSE/PFC 属于网卡/交换芯片能力，本 demo 不伪造控制帧；请在设备驱动和交换芯片配置中启用。
